## 1. What GURU Is

GURU is a multi-module Android application, backed by a Rust cognitive core (cerebrum) and a Rust server engine, that gives a user-connected language model real OS-level agency on an Android phone. Not an assistant. A framework that turns model intent into device action through 57 tool set categories, an on-device memory system, on-device embeddings, Tor-routed networking, and a self-modifying prompt pipeline.

Licence: AGPL-3.0-or-later for the app. Publisher server stays closed source. GURU name/branding are trademarks of Unus Lumen Ltd, Bristol UK.

Founder and developer: Steven Newman. Everything in this repo is his engineering.

## 4. Discrepancies Noted So Far

1. **Cerebrum crate count.** TECHNICAL_ROADMAP.md says "cerebrum (a Rust server with 6 crates)" and lists cerebrum-server, curate, events, policy, graph, query. The actual `cerebrum/Cargo.toml` workspace members list 23 crates: android, cli, cluster, core, crypto, curate, dream, dwm, embeddings, episodic, events, graph, http, mcp, node, policy, prefetch, query, rl, server, signatures, storage, token. The roadmap is out of date. ARCHITECTURE.md says "22+ crates" which is accurate.
2. **Gradle module count.** Roadmap says 30. settings.gradle has 35 includes.
3. **Widget notes case.** As noted in section on widgets: `WidgetUpdaterImpl.updateAll` handles Calendar and Tasks only. No Notes case. Whether deliberate or a gap, TBD.
4. **Calendar widget naming quirk — RESOLVED (misnomer, no bug).** `CalendarWidget.provideGlance` reads `PrefsConstants.EXCLUDED_CALENDARS_KEY` into a val named `includedCalendars`, then passes it as the filter. Verified against `GetAllCalendarsUseCase` (computes `included = id !in excluded`) and `CalendarRepositoryImpl` (every query filters `CALENDAR_ID NOT IN (...)`) and `CalendarViewModel.updateExcludedCalendars` (the IncludeCalendar event passes the PRE-toggle `included` value, and the handler adds to the excluded set when it was true — i.e. unchecking an included calendar adds it to the excluded set). The value is the exclusion list throughout; only the widget's local val name inverts it. Cosmetically wrong, behaviourally correct.
5. **TasksScreen search bug.** The search icon in `TasksScreen` navigates to `Screen.NotesScreen` — not `Screen.TasksSearchScreen`. A fully built `TasksSearchScreen` + `TasksViewModel.searchTasks` pipeline sits right there. Classic copy-paste wiring error. Flagged for the bug workflow.
6. **ProjectsScreen dead controls.** The app-bar search icon's onClick is empty with a `/* TODO: Search */` comment. The ProjectCard overflow menu's "Delete" item has `// TODO: Delete project` and does nothing. The backing `ProjectsViewModel` already implements both SearchProjects and DeleteProject events — only the UI wiring is missing.
7. **ProjectAgent prompt-in-code + legacy path.** `ProjectAgentRepositoryImpl` (portal:data) builds the project-agent system prompt with hardcoded English ("You're Guru, an AI assistant helping with a project.") — the only place in the prompt pipeline with in-code persona text, contradicting the "GURU carries NO prompts in code" doctrine the main chat pipeline follows. It also executes tools through the old koog ToolSet registry (`toolRegistry.tools` + `decodeArgs`/`execute`) rather than the modern ToolDispatcher, has no compaction, no retry ladder, and rides its own LlmConfig fetch per send. A legacy path that predates the registry migration, kept working.
8. **Export encryption plumbed but unreachable.** `ExportJsonDataUseCase`/`ExportMarkdownDataUseCase`/`ImportJsonDataUseCase` all carry `encrypted: Boolean` + `password: String?` parameters. `ImportExportScreen` initialises `val encrypted by remember { mutableStateOf(false) }` and a blank password, renders NO control to change either, and passes them through unchanged. Both export implementations ignore the parameters entirely. Auto-backup (`BackupWorker`) hardcodes `encrypted = false, password = null`. So the encrypted-backup feature exists as an API surface but is dead from every entrypoint.
9. **Thoughts trigger vocabulary gap.** The thought-cycle engine's own docs in the code describe `ThoughtCycleDispatcherWorker` owning scheduling, but the shipped scheduler object is `ThoughtCycleScheduler` (same worker, renamed). Cosmetic doc drift inside comments.
10. **ModuleCanvas shell JS syntax error (live bug candidate).** In `ModuleCanvas.buildModuleShellHtml`, the shell's inline `<script>` block closes its IIFE with TWO `})();` lines in a row (in the Kotlin string, `})(); });` appears twice). One too many closes. If parsed as-is, the JS SyntaxError kills the entire script block: `ModuleRoomData` never defines, `data-module-event` taps never wire, the `GuruBridge` compatibility alias never registers, and `onRoomData` never fires — the room's HTML/CSS still renders but the interactivity layer dies, and the WebChromeClient watchdog (`Uncaught`/`SyntaxError` → `hasRenderError = true`) would surface the "needs attention" card on every room. Verify on-device before touching (bug workflow: logs first — check whether rooms ever showed live data; if they did, confirm the actual parsed form before claiming the bug).
11. **Export/import markdown asymmetry.** Export supports both JSON and Markdown; import offers only JSON (`ImportExportScreen` restricts the import format card to `listOf(UiExportFormat.JSON)` and `ImportDataUseCase` throws for MARKDOWN). A user can export a Markdown tree they can never import back. Consistent with the impl (only the JSON importer exists), but the round-trip promise fails from the export side.
12. **AiProvider enum has an id-6 gap in practice.** The picker renders `provider_unuslumen` as a disabled "Coming soon" item and `ToggleAiProvider` (the master switch) maps ON → `AiProvider.UnusLumen.id` (6). With UnusLumen inference unavailable, toggling the master switch on with no BYO provider selected leaves the app on a provider whose inference path isn't shipped. The ModelConnectScreen flow requires picking a real provider to Save, so this only sticks if the toggle is flipped and the screen abandoned — but the switch state would read enabled against an unconfigured provider.
13. **MediaToolExecutor meme path is hardcoded to the wrong package id (live bug candidate).** `memeSearch`/`memeCreate` in `MediaToolExecutor` shell out to `/data/data/com.unuslumen.app.guru.debug/files/home/openclaw/skills/meme-maker/scripts/meme.mjs` — a hardcoded path matching NEITHER the release applicationId (`com.unuslumen.app.gurubeta`) nor the debug one (`com.unuslumen.app.gurubeta.debug`), and depending on openclaw skill files that are not in this repo. Every meme call fails on a real install. Verify on-device before touching (bug workflow: logs first).
14. **Two cron semantics in the jobs system.** `JobScheduler.kt` carries a REAL 5-field cron matcher (minute-by-minute scan up to 7 days, `*`, `*/step`, ranges, lists, Sunday-as-0 mapping). `JobRepositoryImpl.calculateNextRunForConfig` — which computes the stored `nextRunAt` at create/enable time — uses a documented placeholder for `ScheduleType.CRON` ("Simplified cron - just use next day at same time for now"). The naive value sits in the row until the scheduler's own computation takes over at fire/rebook time. The doc note flagged in section 10 is thus half-right: the repository path IS simplified; the scheduler path is real.
15. **Duplicate OUI keys silently overwrite in the ARP manufacturer table.** `ArpDiscoveryManager`'s handwritten OUI database contains the same prefix under several vendors (e.g. `B8:27:EB` appears as Google (Raspberry Pi), Amazon, LG, Raspberry Pi, and Xiaomi). Kotlin `mapOf` keeps the LAST value for a duplicate key, so `B8:27:EB` resolves to Xiaomi — not Raspberry Pi, the vendor it actually belongs to. Several other prefixes collide the same way (LG/Sony/Linksys blocks, `00:71:47`, `00:15:99`, `00:17:88`, etc.). Cosmetic mislabelling only; the scan itself is sound.
16. **Migration file names are scrambled against their contents.** In `core/database/.../migrations/`: `Migration15To16.kt` actually contains `MIGRATION_16_17`; `Migration16To17.kt` contains `MIGRATION_15_16`; `Migration17To18.kt` contains `MIGRATION_18_19`; `Migration18To19.kt` contains `MIGRATION_19_20`; `Migration19To20.kt` contains `MIGRATION_17_18`. The `val` names inside each file are correct and those are what the registration list wires, so behaviour is unaffected — the mismatch is cosmetic, but anyone opening a file expecting the migration its name promises gets a different one. The 1→15 batch lives in `RoomMigrations.kt`; the 20→26 files carry matching names.

### How the widgets work

All three widgets are `GlanceAppWidget` implementations that also implement `KoinComponent` and inject use cases directly (`GetAllEventsUseCase`, `GetAllTasksUseCase`, `GetAllNotesUseCase` plus `GetPreferenceUseCase`). `provideGlance` reads preferences through flows and collects state inside `provideContent`, so the widgets respect the app's theme (Material You toggle, theme mode, system dark mode) and refresh when preferences change.

**Calendar widget** — reads excluded calendars prefs (value flows into `GetAllEventsUseCase` as a filter, see discrepancy #4), formats each event start with `formatDateForMapping()` to group by day. Shows events grouped under day headers. Refresh button (`RefreshCalendarAction`) calls `CalendarWidget().updateAll(context)`. Add button navigates to `CALENDAR_DETAILS_SCREEN_URI`. Header and event taps navigate to calendar screen / event details via `Constants` URIs into the app's deep-link surface. No-permission state shows explanation plus a button that opens the app's system settings page (`Settings.ACTION_APPLICATION_DETAILS_SETTINGS`).

**Tasks widget** — reads tasks ordering (default `Order.DateModified(ASC)`) and show-completed pref (default false), collects tasks, renders each in `TaskWidgetItem`. Each item has a priority-coloured checkbox (green LOW, orange MEDIUM, red default/high), tapping the checkbox or title fires `CompleteTaskAction` which sends a broadcast to `CompleteTaskWidgetReceiver`. The receiver resolves the task by id and calls `UpdateTaskCompletedUseCase`, then the widget updates because the underlying flow changed. Subtask progress renders as "n/total" with a bullet list icon. Due dates render red when `isDueDateOverdue()`.

**Notes widget** — reads notes ordering (default DateModified ASC) and show-all-notes pref (default false), takes first 10 (`notes.take(10)`), renders pin icon for pinned notes, title with "Untitled" fallback, and a 2-line content preview. Tap navigates to `NOTE_DETAILS_URI/{noteId}`, add button navigates to `NOTE_DETAILS_URI/null`.

**Theme** — `WidgetTheme.kt` defines `widgetDarkColorScheme` and `widgetLightColorScheme` (both built with `darkColorScheme(...)`; the "light" one is a dark scheme with light values — naming quirk only, values are correct for light mode: white container, black text). Both keyed on secondaryContainer/onSecondary/onSecondaryContainer/secondary. When Material You is enabled, `GlanceTheme.colors` is used instead.

**Backgrounds** — `BackwardCompatibleRoundedBackground.kt` provides three `GlanceModifier` extensions: `largeBackgroundBasedOnVersion()`, `largeInnerBackgroundBasedOnVersion()`, `smallBackgroundBasedOnVersion()`. On Android 12+ (S) they use `background(color).cornerRadius(...)`; below that they render a tinted 9-patch-style drawable (`large_item_rounded_corner_shape`, `large_inner_item_rounded_corner_shape`, `small_item_rounded_corner_shape`) tinted with theme colours.

### Widget wiring that lives elsewhere

- `core/widget/WidgetUpdater.kt` — the interface (`WidgetType` enum with Calendar and Tasks) implemented by the widget module's `WidgetUpdaterImpl`. This is how the rest of the app tells the widgets to refresh from code.
- Widget receivers and the `CompleteTaskWidgetReceiver` need entries in the app's AndroidManifest to function; to verify when reading `app/`.
- `Constants` (core:util) provides all deep-link URIs the widget actions use: `TASKS_SCREEN_URI`, `ADD_TASK_ARG`, `TASK_DETAILS_URI`, `CALENDAR_SCREEN_URI`, `CALENDAR_DETAILS_SCREEN_URI`, `CALENDAR_EVENT_ID_ARG`, `NOTES_SCREEN_URI`, `NOTE_DETAILS_URI`.

### Observations

- `WidgetUpdaterImpl` handles Calendar and Tasks but not Notes. The interface enum itself only has Calendar and Tasks, so Notes has no programmatic refresh path at all. Notes widget still updates via Room flow invalidation when data changes and on periodic Glance refresh, so this is a gap, not a break.
- `CalendarHomeScreenWidgetPreview` references `CalendarEvent(id=1, ...)` with positional `location`/`color` params — matches `CalendarEvent` model shape (to verify against the model when reading calendar domain).

## 8. Core Infrastructure (all read in full)

### core:util — Constants, dates, shell, orb, permissions, services

**Constants.kt** — single object with alarm/notification extras (`TASK_ID_EXTRA`, `ALARM_ID_EXTRA`, `ACTION_COMPLETE`), deep-link URIs the widgets use (`app://com.unuslumen.app.guru.tasks`, `.task_details`, `.calendar`, `.calendar_event_details`, `.notes`, `.note_details`) plus arg names (`taskId`, `addTask`, `eventId`, `noteId`), and GitHub links to the public repo.

**date/DateUtils.kt** — the app-wide date/format layer. kotlinx-datetime based. Key functions: `now()`, `Long.localDateTime`, `formatDateDependingOnDay` (time if today, else date+time), `formatDateForMapping` (weekday day, month year — used by calendar widget day grouping), `formatTime` (respects 24h locale), `formatDate`, `monthName`, `isDueDateOverdue` (now comparison — drives red overdue dates in tasks widget), `todayPlusDays`, `at(hours,minutes)`, `withTimeFrom`, `is24HourFormat` (cached). `HOUR_MILLIS` constant. Day/overdue helpers power both app and widgets.

**shell/ShellExecutor.kt** — unified execution ladder: ROOT first (RootShell daemon, UID 0) → ADB (wireless debugging, shell UID 2000) → Runtime.exec fallback (app UID). Also hosts ADB pairing surface: `pairWithAdb(code, port)`, `autoPairWithAdb(code)` (mDNS port discovery), `autoPairAdb()` (fully automatic — opens Developer Options via accessibility, navigates to Wireless Debugging, opens pairing dialog, reads 6-digit code and port from screen text via regex, pairs, presses back twice, reopens GURU). `executeViaRuntime` drains stdout/stderr concurrently to avoid pipe deadlock.

**shell/RootShell.kt** — true UID 0 access. Extracts native rootshell daemon from APK native libs to `/data/local/tmp/guru_rootshell_daemon`, starts via `su -c`, talks over Unix socket at `/data/local/tmp/guru_rootshell` with binary protocol: [4B LE cmd len][cmd] → [4B LE exit][4B LE stdout len][stdout][4B LE stderr len][stderr] (bounded 1MB). Falls back to `su -c` per-command. Has `attemptExploit()` that extracts and runs a bundled exploit runner (`libexploit_runner.so`) looking for "EXPLOIT SUCCEEDED" in output — for security research on owned devices. su searched across 11 common paths.

**shell/AdbClient.kt** — full ADB wire protocol in Kotlin: CNXN/AUTH/OPEN/OKAY/WRTE/CLSE/STLS, TLS upgrade (Android 11+), RSA AUTH (token signing with PKCS#1 v1.5 SHA-1 DigestInfo, two-stage signature-then-publickey with circuit breaker), ADB public key encoding (modulus_size_words, n0inv, little-endian modulus, rr = R^2 mod N, exponent, base64 + " guru@guru"), shell session open/read-loop (cap 200 messages). `ShellResult` data class lives here. Deliberately no timeouts ("AGI doesn't have timeouts").

**shell/AdbPairingClient.kt** — wireless debugging pairing: TLS to pairing port (self-signed cert key manager, all-trusting trust manager), export TLS keying material via Conscrypt reflection (fallback HKDF), SPAKE2 with password = pairingCode + keyMaterial, AES-128-GCM peer info exchange with sequence-based nonces, pairing packet format [1B version][1B type][4B BE payload size]. 3 retries with progressive backoff.

**shell/Spake2.kt** — pure Kotlin SPAKE2 matching BoringSSL exactly. Ed25519 extended coordinate arithmetic (point add/negate/scalar mult), Montgomery u-coordinate conversion both directions, X25519 via Android XDH KeyAgreement with manual Montgomery ladder fallback, M/N constants computed by hash-to-curve ("M-Ed25519"/"N-Ed25519" seeds, SHA-512, clamp, scalar mult, to-Montgomery), HKDF-SHA256 key derivation with info "adb pairing_auth aes-128-gcm key". Client names "adb pair client\0"/"adb pair server\0".

**shell/AdbKeyStore.kt** — persists ADB RSA key pair (2048-bit) as hex strings (modulus/publicExponent/privateExponent) in filesDir/adb_key. Cached in memory. Comment claims Keystore encryption but implementation stores plaintext hex — observation.

**shell/SelfSignedCert.kt** — generates X509 self-signed certs via manual DER encoding (TBSCertificate: version v3, serial, SHA256withRSA algorithm id, issuer/subject X500Principal, UTCTime/GeneralizedTime validity 30y, RSA public key encoded), signs, wraps in Certificate SEQUENCE, validates by re-parsing through CertificateFactory, falls back to simpler encoding on mismatch.

**shell/AdbMdnsDiscovery.kt** — NSD-based discovery of `_adb-tls-pairing._tcp` and `_adb-tls-connect._tcp` services. Suspend wrapper over NsdManager callbacks.

**shell/AppRuntimeExec.kt** — single clean path for bundled binary execution from nativeLibraryDir (nativedir_file SELinux label = only exec-allowed location from app UID). ProcessBuilder direct argv (never sh -c), concurrent stream drain threads, hard timeout with destroyForcibly. Used by vision stack (tesseract, ffmpeg).

**shell/PythonProvider.kt** — bundled Python 3.14. ## 10. Portal — the brain of the app

### The prompt architecture (important finding)

**All app-side prompt constants are empty shells.** GuruIdentity, GuruCapabilities, GuruContext, GuruBrain, GuruReflection, GuruPrompts, GURU_SPINNER_VERBS are all empty strings with comments like "Content moved to server database (master_prompts, category: context)". The real system prompt is composed server-side at `https://api.unuslumen.com/prompts/assembled`, fetched by PromptFetcher over TorEgress, cached in SharedPreferences (guru_prompts), and served with `${human}` token substitution at read time by PromptRepositoryImpl using the USER_NAME_KEY preference (fallback "your human", so the raw token never reaches the model).

This confirms the README's "GURU disconnected from its publisher boots but does not work as intended" — with no publisher and no hand-installed prompts, the system prompt is empty. GuruLuxify is the exception: it's a real code-built section listing active skills, instructing useSkill/searchSkills usage. AiConstants has MAX_CONSECUTIVE_TOOL_CALLS = 15000 and empty note-prompts.

PromptModels define the amendment system: PromptSection (masterContent, isEditable, amendments), PromptAmendment (type ADD/MODIFY/REPLACE, proposedBy USER/GURU, status PENDING/APPROVED/REJECTED/ROLLED_BACK, rationale, version), AssembledPrompt(s), PendingApprovalsSummary. The DB-backed section pipeline (PromptSectionEntity/PromptAmendmentEntity) is the self-modification channel described in ARCHITECTURE.md.

### AiRepositoryImpl — the send pipeline (read in full, ~2300 lines)

The complete engine. Key facts:

**Init**: `rebuildModelWiringOnce()` on applicationScope. Reads AI_PROVIDER_KEY (default UnusLumen). Migrates legacy string-stored ai_tools_enabled boolean (the savePreference tool bug: everything saved as string, silently breaking tool calling — now fixed with a try/catch ClassCastException guard). Reads toolsEnabled (default true), visionEnabled (default false), humanName.

**Provider paths**:
- None → no model, nothing initialised.
- BYO (any of OpenAI/Anthropic/Google/XAI/Ollama/OpenAICompat) → `initializeByoProvider`: reads BYO_API_KEY/BASE_URL/MODEL_NAME from prefs; cloud brands ride koog brand clients (OpenAI/XAI share OpenAILLMClient with different baseUrl, Anthropic uses AnthropicModels.Sonnet_4_5.copy(id=userModel), Google uses GoogleLLMClient); Ollama/OpenAICompat ride the app's own UnusLumenClient/UnusLumenStreamingClient pointed at the user's URL. - UnusLumen/default → LlmConfigFetcher (server model config: baseModel, fallbackModels, contextWindow, maxTokens etc.), model.toLLModel, UnusLumenClient against api.unuslumen.com, UnusLumenStreamingClient on shared TorEgress client, PromptFetcher, fallback models loaded from server config.

**Sync loop**: exactly-one guard via AtomicBoolean (because @Factory can mint multiple instances, each would launch its own 6h loop). SkillLibrarySyncWorker.syncNow every 6h, offline-tolerant.

**sendMessage** flow:
1. Model + executor required, else throw AiRepositoryException.
2. Fetch fresh LlmConfig per send for UnusLumen (superadmin changes land without restart); BYO reads its wire options from device prefs (BYO_TEMPERATURE/MAX_TOKENS/CONTEXT_WINDOW/THINKING_LEVEL/TOP_P/TOP_K/REPEAT_PENALTY/SEED) falling back to LlmConfig defaults.
3. HookEventBus.fire(MESSAGE_SENT).
4. memoryRepository.buildContextPreamble(userMessage, humanName, messages) → preamble.
5. Notes-to-self: NotesToSelfEngine(dao).matchingContent(userMessage) → keyword-triggered notes injected as a block "Notes to yourself (triggered by what X just said...)".
6. enrichedSystemMessage = chatSystemMessage + memory context + notes-to-self (four-way when).
7. Conversation create/update/recreate with truncateTitle(77).
8. do/while tool-call loop:
   - Guard: consecutiveToolCalls >= MAX_CONSECUTIVE_TOOL_CALLS (15000) → ToolCallLimitExceeded.
   - Tool descriptors: builtin definitions via GuruToolSchemaMapper + guruToolRegistryManager.getGuruToolDescriptors() — full parameter schemas, not name+description (documented fix).
   - Tool definitions for the Ollama wire: registry + guruToolRegistryManager.refreshToolDefinitions(builtin).
   - Model chain: primary + fallbacks.
   - Layer 2 compaction: when tokenEstimate > contextWindow * thresholdPercent/100 and compaction.enabled, ContextManager.performAutoCompact with server summaryPrompt + keepRecent; DB-FIRST (history already persisted, compaction only reshapes the LLM's view); compactionPointerText carried.
   - Metadata block per iteration: MetadataConfigFetcher per send; MetadataAssembler.assemble with session/messages/tokens/compacted → injected when injectOnReceive.
   - Layer 1 microcompact: ContextManager.microcompact strips old tool results.
   - Vision: per-send pref refresh; ImageTurnAssembler.assemble turns file paths into image blocks (cap 4); captureFailed → in-band system note telling the model its eyes are dark (honest failure, documented). Streaming client reads assembledImages; koog brand clients get images stitched as ContentPart.Image on the last user message (documented double-delivery guard).
   - Streaming: streamingClient?.executeStreamingWithTools (Ollama wire) ?: koog executor.executeStreaming (cloud). Frames: TextDelta/TextComplete/ReasoningDelta/ReasoningComplete/ToolCallDelta/ToolCallComplete/End. StreamingAssistant emissions with partialContent + partialThinking.
   - Tool calls collected → executeToolCallFromFrame: guru-defined tools via guruToolRegistryManager, registry tools via toolDispatcher.dispatch, fallback through dispatcher name resolution. Results → AiMessage.ToolCall + ToolCallResultObject extraction for rich UI cards (100+ tool names mapped to typed card objects for notes/tasks/calendar/journal/bookmarks/alarms/memory/plans/web/settings/sound/media/smarthome/weather/places/github/trello/notion/voice/communication/system/email/camera).
   - LLMClientException retry: retryable on 503/overloaded/temporarily/Connection refused/ConnectException/500/timeout, 4 retries with progressive backoff, then fallback model, then throw.
   - Tool results persisted to tool_results table (truncated result+params, flattened text, TTL by tool, SignatureEngine signature, success heuristic).

### CerebrumBrainApi.kt — the wire contract (single file owns all brain JSON)

Key mechanics:
- Deterministic brain id: sha256(content + ":" + len) → 64 hex. Same content = same id = idempotent upsert, never duplicates.

- CurateAck parses executed.success + side_effects counts (created/updated/merged/deleted/dwm_count/hamming_count/graph_nodes/graph_edges/events/cross_references).
- searchFacts: SEARCH frame {query, radius:64, limit}; hits = array of {memory_id:[32 bytes], score, content}.
- retrieveDeepOrShallow: RETRIEVE {memory_id, level:Deep|Shallow}; body decodes to domain/topic/subtopic/content/decay tuple [layer,strength,accesses,archived]/episode presence.

## 11. Cerebrum — the Rust Cognitive Core

A separate Cargo workspace at `GURUbeta-FULL/cerebrum/` with 23 crates. Built separately and shipped two ways: as `libcerebrum_android.so` (cdylib JNI host for the app) and as `cerebrum-server` (the standalone server binary + unix/TCP front doors). The whole cognitive system. Read so far: cerebrum-core, cerebrum-signatures, cerebrum-dwm (lib + dynamic_wavelet_matrix), cerebrum-android, cerebrum-server (state + handler).

### cerebrum-core — the contracts every crate depends on

- **MemoryId**: 256-bit (32-byte) id, hex display, random from two concatenated UUIDv4s.
- **BinarySignature**: 32-byte binary vector. xor, popcount (Hamming weight), hamming_distance (popcount of XOR). The compressed replacement for 768-dim float vectors (96x size reduction before DWM compression).
- **TokenSequence**: raw (uncompressed) token IDs + vocabulary_id; cerebrum-token compresses further via delta+zigzag+varint.
- **ContextEntry**: the curated memory shape — memory_id, domain → topic → subtopic → content, relations, provenance, rationale, created/modified timestamps.
- **CurateOp**: the five operations (Add / Update / Upsert / Merge / Delete), every one carrying a reason (full auditability). Delete is "archive — Constitution §5" (the No-Delete principle).
- **QueryType**: Semantic / Temporal / Causal / Entity / Composite — the four orthogonal graph views + combined.
- **TokenBudget**: max/used, consume() errors on overrun. Query type pairs with it.
- **DereferenceLevel**: Shallow (index only) / Deep (full artifact) / Partial { sections } with a manual Hash impl.
- **GraphEdge**: edge_type + source + target + weight + timestamp. **TraverseStrategy**: Bfs/Dfs/Weighted/Temporal.
- **Event**: event_id (Uuid), event_type, memory_id, payload (serde_json::Value), timestamp, EnrichmentStatus (Pending/Enriched/Failed/DeadLetter). CortexDB event-sourcing pattern.
- **Episode**: the full context of how a memory was discovered — source, trigger, context, discovered_at.
- **Frame** enum: Query / Curate(Box<CurateOp>) / Retrieve / Search{signature,radius,limit} / GraphTraverse{start,edge_type,depth} / Consolidate / Prefetch. Frame type bytes: QUERY=0x01, CURATE=0x02, RETRIEVE=0x03, SEARCH=0x04, GRAPH_TRAVERSE=0x05, CONSOLIDATE=0x06, PREFETCH=0x07, RESPONSE=0x80, ERROR=0x81. FrameTag with TryFrom<u8> and From<Frame> for u8.
- **CerebrumError**: DwmError/SignatureError/TokenError/GraphError/StorageError/QueryError/NotFound/BudgetExceeded.
- **Traits**: SignatureGenerator (generate/generate_batch/hamming_distance/hamming_ball), DwmStore (insert/remove/search/reconstruct/count/persist/load), GraphView (add_edge/traverse/traverse_bounded with a real default depth-limited BFS including Weighted ordering/neighbors), EventStore (append/append_event/events_for/unenriched/mark_enriched).

Property tests (proptest, 10K cases) cover XOR identity/commutativity/associativity, popcount bounds, Hamming metric properties (symmetry, triangle inequality, ≤256), MemoryId uniqueness, token budget arithmetic, and frame-tag roundtrips. Extensive unit test suite.

### cerebrum-signatures — THE compressed representation layer

Pipeline from arXiv:2602.13594. **256-bit signatures replace 768-dim float vectors = 96x reduction; search becomes popcount.**

- **SignatureConfig**: context_dim 10,000, signature_bits 256 (128/512 supported, must be multiple of 8), sparsity 0.01, ThresholdStrategy (Median default / Fixed / Adaptive), seed. Validated.
- **RandomIndexing**: generates a random projection matrix (context_dim × sig_bytes) using a built-in **PCG-XSH-RR RNG** (reproducible, no rand crate overhead) with Box-Muller normal entries scaled 1/sqrt(context_dim). `generate_from_tokens` builds a TF-weighted sparse context vector, projects it (skipping zeros — sparse optimisation), and binarizes. `generate_from_embedding` is the fallback path. `binarize` supports median (sorted midpoint), fixed, and adaptive (mean + 0.5σ) thresholds.
- **HammingSearcher**: linear SIMD scan for small collections; **multi-index hashing** for >100K entries (auto-builds). Pigeonhole principle: if total Hamming distance ≤ radius, some substring of 32/num_substrings bytes has distance ≤ radius/num_substrings — so hash-table the substrings. `search_multi_index` does exact-substring lookups first (O(1)), expands to near-matches when short on candidates, verifies every candidate with full Hamming distance. Splits 32 bytes into 2…8 substrings.
- **SignatureEngine**: the SignatureGenerator impl. text → HashTokenizer → token IDs → RandomIndexing → BinarySignature, plus the searcher index. Default production tokenizer is HashTokenizer (deterministic word hashing); `with_tokenizer` accepts any BPE/WordPiece/SentencePiece.
- simd module re-exported: hamming_distance_fast/scalar, batch8, is_avx2_supported. AVX2 processes a whole 256-bit signature in 1 XOR + 4 popcounts.
- Utilities: collision_analysis (pairwise % under a distance threshold), mean_hamming_distance.

### cerebrum-dwm — THE core invention

"First public implementation of arXiv:2602.13594 on Earth." Co-indexes binary signatures AND token-ID sequences in ONE structure. Search by semantic similarity (Hamming ball) WITHIN the compressed domain; exact token reconstruction with no information loss. Claims 31x faster retrieval than vector methods, 14x smaller memory.

- **SuccinctBitVec** (O(1) rank, O(log n) select) → **WaveletTree** (static integer sequences) → **DynamicWaveletTree** (insert/delete with amortised O(log n × log σ)) → **DynamicWaveletMatrix** (the co-index) → **DwmPersistence** (memory-mapped files + WAL + snapshots).
- **DynamicLevel**: a DynamicSuccinctBitVec + boundaries (the single 0-boundary per level; navigation: bit=0 → rank_0(pos); bit=1 → boundary + rank_1(pos)).
- **DynamicWaveletMatrix** fields: levels (signature_bits DynamicLevels), alphabet_size, signature_bits, n, token_dwt (shares position ordering), token_vocab_id, sig_data (rebuild store), id_to_pos, id_to_sig_idx, memory_ids (level-0 order), leaf_to_level0 (maps level-256 leaf position back to level-0; the orderings differ because level 0 = lexicographic byte sort and level 256 = LSB-first radix sort), subblock_maps + maps_k/maps_sub_size/maps_n (precomputed leaf positions per sub-block boundary for O(1) lookup — the multi-index fast path).
- **Insert**: per-level dynamic insertion (O(log n × signature_bits)) with boundary maintenance; metadata shifts; caches invalidated. **Batch insert**: one rebuild. **Delete**: per-level dynamic deletion, returns leaf position for metadata cleanup.
- **Search (multi-index)**: K = radius + 1 sub-blocks (pigeonhole), sub_size = signature_bits/K, sub_radius = radius/K. Each sub-block searched recursively with `search_levels_range` (follow query bit at no cost, try the opposite at +1, prune over radius). Candidates mapped from sub-block position → leaf → level-0 via precomputed maps (fast) or navigate_to_leaf (fallback), sorted+dedup'd, verified against the full signature. Early termination when limit already filled with distance-0 hits.
- Reconstruction: reconstruct_signature (level-by-level navigation, O(bits)) and reconstruct_tokens (via token DWT, lossless).
- The test suite is forensic: batch-vs-brute-force equality, full 32-byte signature tests, interleaved insert/delete/search integrity with after-every-mutation invariant verification, 1000-insert boundary-drift checks, 512-boundary-per-insert checks, 10K-signature stress. Debug-only asserts cross-check multi-index against brute force on every search. This is not test theatre — it's the engineering of a structure where a boundary drift corrupts everything.

### cerebrum-android — the JNI host (Phase F)

The cdylib the Android app loads. Kotlin talks ONLY to these exports. Payloads cross JNI as lowercase hex both directions — the exact same bytes the unix/TCP front doors exchange. **The passphrase arrives once through JNI and lands in a `Zeroizing<String>` inside the brain holder only.** No log line sees it; no clone outlives stop.

- **AndroidBrain** struct: state (Arc<TokioMutex<CerebrumState>>), passphrase_ram (Zeroizing, RAM only), data_dir, socket_path, listener/save-loop aliveness atomics, dirty_generation counter, started_at, requests_handled.
- **Trailing-save watcher** (hard-close data-loss fix): the 5-minute tick alone loses up to 300s of writes on a process kill. Every MUTATING frame (curate/consolidate — the execute export matches frame_type 2|6) bumps a global dirty counter; the watcher saves 10 seconds after the LAST bump. A brain hard-killed loses at most 10 seconds.
- **Unix socket listener**: removes a stale socket, binds, accepts connections, each connection runs a frame read→handle_frame→write loop. Errors return an ERROR frame carrying the message.
- **boot**: empty passphrase refused (fail closed); restore_state from the encrypted vault; installs a no-network hardening filter; spawns the save tick + listener. **stop**: takes the brain handle out first (nothing can call into a mid-stop brain), stops loops, final save, removes the socket, and wipes the Zeroizing passphrase slot.
- JNI exports match CerebrumHost.kt: cerebrumStartJNI → stamp or 0; cerebrumStopJNI; cerebrumSaveNowJNI → records written; cerebrumExecuteJNI(frameType, payloadHex) → reply hex (marks dirty on curate/consolidate); cerebrumStatusJNI → status JSON (running, save_loop, uptime_ms, requests, engines{memories,dwm,events,graph_nodes}, socket); cerebrumLastErrorJNI.

### cerebrum-server — state + handler (the brain in full)

**CerebrumState** holds every engine: QueryTypeClassifier + QueryEngine + hot_cache, ContextTree + CrossReferenceEngine, InMemoryStorage + WriteAheadLog + SnapshotManager, DecayEngine, GraphStore (all four views) + GraphQueryPlanner, DreamEngine, PrefetchEngine, EpisodicStore, SignatureEngine, DynamicWaveletMatrix, EventStore, EmbeddingEngine (TF-IDF fallback), IndexedExperienceStore, last_curated_id, data_dir. Helpers hot_cache_forget / hot_cache_insert_wide (the two cache surfaces kept in sync).

**handle_frame** dispatches by frame type to the seven handlers. This is the full pipeline:

- **QUERY**: classify → sign the query → search both the SignatureEngine and the DWM → dedup by id keeping best distance → graph neighbours for the classified view → derive candidate signatures from tree contents → QueryEngine.plan + execute across tiers → decay_engine.access() on every returned result (the hot-memory strengthening pass).
- **CURATE**: deserialize ops → convert to CurateOperation → **execute the full batch through CurateExecutor (validated, atomic, rollback)**; a failed batch returns success=false as a valid outcome, not an error frame → write-through WAL (append_delete for deletes, append_put carrying the reason for mutations) → **Pass 2: propagate each applied op into every other engine** via apply_post_tree_pipeline.
  - **run_full_add_pipeline** (16 steps): tokenize + sign; insert into DWM (co-indexed with tokens) + Hamming index; decay Buffer layer; event append; cross-references against same-context entries in other domains sharing non-stopword concepts (confidence 0.6); temporal edge from last_curated_id (Before); semantic edges (signature radius 16, weight 1−dist/256, cap 24); entity edges (shared capitalised tokens → InvolvedIn 0.8, metadata=entity); graph label (domain topic subtopic content); prefetch register; episodic record (heuristics: content >50 chars and (important/discovered reason or >160 chars)); embedding build; experience index (summary capped 100 chars); hot cache warm.
  - **update**: remove old DWM/Hamming entries, insert new, rebuild edges, decay content, event, graph label, embedding, experience summary, hot cache, prefetch.
  - **merge**: insert target, decay Semantic layer, event with source ids, pipeline-remove every source, rebuild edges+label, last_curated_id=merged, prefetch, hot cache, embedding.
  - **delete**: pipeline remove (DWM, Hamming, cross-refs, hot cache), archive in decay (No-Delete), event.
  - Response carries the CurationResult + CurateSideEffectsSummary (created/updated/merged/deleted/dwm_count/hamming_count/graph_nodes/graph_edges/events/cross_references/episodic/hot_cache/experience_store).
- **RETRIEVE**: tree find (body) + decay access (lifecycle metadata with strengthening) + episodic reconstruct (full context + valence) + cross-references both directions. Shallow = id/domain/topic/subtopic/decay; Deep = + content/episode/referencing/referenced_by; Partial = paragraph split matched against requested section keywords (whole-content fallback).
- **SEARCH**: radius 64 (12.5% per the plan's Phase 3), search both indices, dedup best distance, real contents from the tree, decay strengthening on found, score = 1 − dist/256. Substring scan fallback for exact strings.
- **GRAPH_TRAVERSE**: GraphStore.query with the planner.
- **CONSOLIDATE (the dream pass)**: decay_all + consolidate (life-stage transitions: Buffer→Episodic→Semantic, archivals) → build DreamMemory records with pairwise similarity from signatures (merge/dedup thresholds) → dream_engine.consolidate() → apply merge/dedup results across DWM/Hamming/decay (pipeline_remove_by_id) → enrich all pending events → **entity reconciliation sweep** (same-referent label dedup, edge rewire, alias rows). Returns ConsolidationReportFull (decayed_all/buffer_promotions/episodic_promotions/archived/dream_results/merged_into_dwm/removed_from_dwm/events_enriched/entities_reconciled/aliases_recorded). The Kotlin side reads "decayed_all" from this.
- **PREFETCH**: prefetch_engine.prefetch(trigger).

### cerebrum-embeddings — the fallback embedding lane

TF-IDF + random projection, no neural net. `EmbeddingEngine`: vocabulary (word → index) built from a hashed TF-IDF space, **FNV-1a hashing** for token → bucket, random projection down to 256-dim, **L2 normalisation** on output. Serves as the PgVectorFallback tier's embedding producer and the `IndexedExperienceStore` embedding path. This is the sovereign, offline, deterministic alternative to float-vector embeddings — same 256-dim budget the signature layer uses.

### cerebrum-token — the compression pipeline

Token sequences compress through delta encoding + zigzag + varint, then reconstruct losslessly. `TokenSequence` carries raw IDs + vocab id at the core layer; this crate does the storage compression. Ships HashTokenizer and SimpleTokenizer implementations (HashTokenizer is the production default via SignatureEngine). Submodules (compress/error/reconstruct/tokenizer/varint/vocabulary) exist but the lib.rs was read in full; individual submodule files remain for a later pass.

### cerebrum-crypto — the vault

The encrypted-at-rest layer for everything the brain stores.
- **KDF**: Argon2id, **m=262144 KiB (256 MiB), t=3, p=1** — a memory-hard params set sized for a phone.
- **Cipher**: XChaCha20-Poly1305 (extended-nonce, so no nonce-reuse anxiety across restarts).
- **File format**: 115-byte header, then records. Per-record nonce = file nonce base XOR record counter, with the counter bound into the AAD — so reordering or replaying records fails authentication. Submodules (error/header/record/vault) exist; lib.rs read in full.

### cerebrum-episodic — the episode store

`EmotionalValence` enum: Exciting / Concerning / Routine / Surprising — the emotional colour of a memory's discovery. `RichEpisode` carries the full discovery context (source, trigger, context, valence, timestamp). `EpisodicStore` capped at **10,000 episodes, evict oldest first**. The episodic layer is the middle life-stage: Buffer → Episodic → Semantic.

### cerebrum-decay — the memory lifecycle engine

Three `MemoryLayer`s with real half-lives:
- **Buffer**: 1-hour half-life (the scratchpad layer — a memory must prove itself fast).
- **Episodic**: 30-day half-life.
- **Semantic**: no decay (earned permanence).

Mechanics: strength decays exponentially with time since last access; **hibernation threshold 0.01** (below this the memory sleeps but never dies); **archive at 90 days** (archived, not deleted — No-Delete); **consolidation trigger at 100** decayed items. Promotion paths: Buffer → Episodic on access; Episodic → Semantic after ≥3 accesses. Access strengthens (the `decay_engine.access()` call in every QUERY/SEARCH/RETRIEVE path).

### cerebrum-curate — the curation layer

- **ContextTree**: the domain → topic → subtopic hierarchical tree every memory lands in. The tree is the organisational spine; the DWM is the search spine.
- **CurateExecutor**: executes CurateOps **atomically** — pre-validate the whole batch, apply, and roll back every applied op if any op in the batch fails. A curated batch is all-or-nothing.
- **CrossReferenceEngine**: bidirectional cross-references between entries sharing context, each with provenance (which entry pointed at which, why).

### cerebrum-events — the event spine

`EventStore` is **append-only** — the event log is the audit trail of everything the brain ever did. `Enricher` extracts sentence-level facts from raw event payloads. `ReplayState` tracks replay progress so the log can rebuild derived state. This is the CortexDB event-sourcing pattern the core crate's Event type references.

### cerebrum-graph — the four orthogonal views

Four graph views matching QueryType: **Semantic, Temporal, Causal, Entity**. `GraphStore` holds all four; `GraphQueryPlanner` picks traversal strategies per query type and start-node heuristics. Cross-view fusion uses **Reciprocal Rank Fusion, k=60**. `QueryTypeClassifier` runs first on every QUERY frame to route. Benchmark: 10k nodes traversed in under 10ms. The entities submodule (entity extraction/reconciliation used by the CONSOLIDATE sweep) exists; lib.rs read in full.

### cerebrum-dream — the consolidation engine

`DreamEngine`: builds DreamMemory records with pairwise signature similarity, then runs the four-phase consolidation:
1. **Merge** at similarity ≥ 0.8 (near-duplicates fuse into the stronger memory).
2. **Dedup** at ≥ 0.95 (effective-duplicate kill).
3. **Semantic upgrade** (Episodic → Semantic promotions for proven memories).
4. **Prune** at 90 days (archive, never delete).

The CONSOLIDATE frame runs this plus decay_all plus entity reconciliation.

### cerebrum-policy — the dereferencing policy

- `IndexEntry`: lightweight index row (id, summary, signature pointer) — the shallow tier.
- **DereferencingController**: decides Shallow vs Deep retrieval **tiered by token budget consumption**: above 80% budget → shallow only; below 50% → deep allowed; between → partial. The brain never blows its own context budget fetching memory bodies.
- **PolicyNetwork**: hand-coded (not trained) policy weights — deterministic, debuggable.
- No-Delete: policy archives; nothing in the policy layer can delete.

### cerebrum-query — the tiered retrieval engine

Four `RetrievalTier`s with latency envelopes:
- **HotCache** — under 1ms (recently touched entries, RAM).
- **DwmSearch** — under 50ms (signature search in the DWM).
- **GraphTraversal** — under 100ms (relationship-walking).
- **PgVectorFallback** — under 500ms (embedding nearest-neighbour).

`QueryEngine.classify → plan → execute` routes through the tiers in order; `ConfidenceRouter` promotes/demotes result confidence (0.8 / 0.5 thresholds) to decide whether a lower tier even needs to run.

### cerebrum-storage — durability

- `StorageEngine` trait (put/get/delete/iterate).
- **WriteAheadLog**: append → checkpoint → recover — every mutation hits the WAL before the tree is touched; replay rebuilds state after a hard kill.
- **SnapshotManager**: max 5 rotating snapshots.
- `InMemoryStorage` implements the trait for tests.

### cerebrum-prefetch — the anticipation engine

`PrefetchEngine` triggers: **SpecialistActivated** (a tool/agent starts → warm related memories), **TopicShift** (conversation moved topic → pull the new neighbourhood), **ScheduledEvent** (time-based warm-up). Keyword heuristics (not a model) — cheap, on-device, deterministic. Wired to `prefetch register` inside the curate pipeline so every new memory is reachable warm.

### cerebrum-rl — the training loop

Three-stage trainer: **SFT → Reward → GRPO** (group relative policy optimisation). `TrainablePolicy` thresholds: relevance 0.5, budget 0.5, archive 0.2. `RewardModel` scores three criteria: task completion, memory efficiency, budget adherence. Smoke tests present. This is the brain's own improvement lane — the policy network's future trained successor.

### DWM internals — the four layers under the matrix (all read in full)

**succinct.rs — SuccinctBitVec (static).** Two-level rank sampling: `rank_blocks[w]` = cumulative 1-count in [0, w*64) with a sentinel at the end holding the total, so `rank1(i)` is one array lookup plus one popcount (O(1)). Select sampled every 64th occurrence (`SELECT_RATE=64`) in `select_blocks_0`/`select_blocks_1`, then binary search within the sampled range (O(log n)). `from_bytes` maps MSB-first (bit i = `(bytes[i/8] >> (7 - i%8)) & 1`). **Mutation is O(n)** — push/set/insert/delete all trigger full `rebuild_indices()`, and insert_bit/delete_bit collect the whole vector and rebuild from scratch. The module doc is explicit: this is the static workhorse, and the O(n) mutation is why the dynamic variant exists. Property tests 10K cases. The file carries an old comment trail about the production optimisation path.

**dynamic_succinct.rs — DynamicSuccinctBitVec (the real one the DWM uses).** 512-bit blocks (8 u64 words, one cache line), each block tracking `data[8]`, per-word prefix sums `word_ones[8]` (so local rank1 is O(1) not a loop — documented as the fix for old loop-based rank dominating query time), `len`, `ones`. TWO Fenwick trees: one over block one-counts (rank queries, `lower_bound` via binary lifting), one over block lengths (`len_fenwick`, replacing an old O(B) linear prefix array — locate() is now O(log B)). Insert: bitwise shift-and-carry across the block's u64 words (no heap alloc, O(8)), split the block at midpoint if full. Delete: reverse shift-and-carry, merge with a neighbour when the block drops below 512/4. `push` is the O(1) amortised append fast path. Complexity table in the header: access O(log B), rank O(log B), insert O(BLOCK_SIZE + log B) ≈ 500x faster than the static rebuild. **The tail of the test module is a forensic debugging archive** — a long series of tests reproducing a rank bug during DWM-pattern insertions (`test_rank_dwm_multi_level_simulation`, `test_rank_exact_level0_sequence`, `test_rank_and_fenwick_after_513_inserts` with block-structure dumps and fenwick cross-checks at 513 inserts, the exact point where the old boundary bug bit: 513 = 512 + 1, the first block split). These tests are now green and stay in place as regression guards.

**wavelet_tree.rs — WaveletTree (static).** Sequence of ints over alphabet [0, σ), one SuccinctBitVec per level, bits-per-symbol = ceil(log2(σ)). Build: level by level, stable-partition by the current bit (zeros then ones), so each level's vector is the bit at that depth. Access navigates top-down: bit=0 → rank_0(pos); bit=1 → zeros_total + rank_1(pos). Rank uses the partition-window algorithm (track pos + partition_start per level; leaf level returns rank within the partition window). Select works bottom-up: start from k in the leaf partition, then `select` at each level upward to map back to the parent position, final position minus 1 (select is 0-indexed vs the +1 correction). Tests cover empty, single, binary, larger alphabet, sequential.

**dynamic_wavelet_tree.rs — DynamicWaveletTree.** The honest middle layer. **The red-black tree scaffolding (`Color`, `WtNode` with left/right/parent/color/size/priority) is declared but dead code** — `#[allow(dead_code)]` with the comment "Reserved for future balanced-tree dynamic bit vector". **persistence.rs — DwmPersistence.** Snapshot format: 24-byte header (magic "DWM\x01", version u32, signature_bits u32, token_alphabet_size u32, count u32, token_vocab_id u32) then per memory: 32-byte MemoryId, 32-byte BinarySignature, u32 token count, N × u32 tokens; footer = CRC32 (IEEE polynomial, hand-rolled) of everything above. `snapshot()` writes to .tmp then atomic rename; `load_mmap()` uses memmap2 with CRC verified over the mapped bytes before parsing; `recover()` = mmap-load snapshot (buffered fallback) + WAL replay. ### cerebrum-crypto internals (all read in full)

**error.rs** — the CryptoError enum: IoRead, IoWrite (message notes "no partial plaintext was ever stored"), EmptyEnvelope, HeaderRejected, MissingHeaderMagic, HeaderLayoutMismatch, HeaderKdfMismatch, Argon2Failure, PassphraseRejected (deliberately non-specific: "wrong passphrase or the vault file is damaged/tampered" — one blanket reject, no oracle), AeadOpenFailed, AeadSealFailed, FileAlreadyExists (fresh-create refuses to clobber), RandomSourceFailed, MalformedRecord, RecordLengthAbsurd, UnknownRecordFrame.

**header.rs — the 119-byte fixed V1 header.** Layout: magic "CERB" (0x43 0x45 0x52 0x42), version u32 LE, header_len u32 LE (must equal 119 or reject), m_cost u32, t_cost u32, p_cost u32, 19-byte salt, 12-byte verifier nonce, 32-byte verifier ciphertext (16-byte plaintext + 16-byte tag), 32-byte file id. KDF sanity ranges enforced on parse AND encode: m 8 MiB–4 GiB, t 1–1024, p 1–4. Defaults: m=262144 KiB, t=3, p=1. The doc comment counts the layout arithmetically: "24 + 19 + 12 + 32 + 32 = 119". Tests: exact roundtrip, wrong version, wrong magic, out-of-range KDF params both directions (encode refusal and on-disk lie detection), wrong reported length, short bytes.

**record.rs — the record cipher layer.** `RamKey`: Zeroizing<[u8;32]>, non-copyable, redacted Debug, zeroize on drop and explicit erase. `RecordNonceCounter`: monotonic per-session u64. `record_nonce(base, counter)`: base nonce with the low 8 bytes XORed with the counter LE. **AAD = "cerebrum-record-v1" tag ‖ counter LE u64 ‖ 32-byte file_id** — binds every ciphertext to its exact position and file, so transposition, mid-stream deletion, or cross-vault transplant all fail at AEAD open. On-disk record = 24-byte nonce ‖ ciphertext‖tag. AAD constants for verifier and nonce-derive domains declared here (construction lives in vault.rs). Constants: RECORD_NONCE_LEN=24, AAD_RECORD_TAG, AAD_VERIFIER_TAG, AAD_NONCE_DERIVE_TAG.

**vault.rs — EncryptedVault + VaultBuilder.** The full file-level IO built on header+record.
- `VaultBuilder::create_from_passphrase`: refuses existing paths (FileAlreadyExists — no clobbering), CSPRNG salt/nonce/file_id via getrandom, Argon2id derivation (V0x13, params validated, output in a Zeroizing), verifier seal = XChaCha20-Poly1305 over the fixed 16-byte `b"cerebrum-verify1"` plaintext under a 24-byte nonce (stored 12 bytes ‖ 12 zero bytes) with AAD bound to MAGIC‖version‖salt‖m‖t‖p — so a verifier block transplanted to a different vault fails. Atomic create: write temp file, fsync, rename over final, fsync the parent dir too.
- `open_existing`: parse header → Argon2id with the header's salt+params → verify the verifier record → any failure becomes one blanket `PassphraseRejected` (documented: never reveals wrong-key vs damage).
- Record stream starts at offset 119. `record_count()` walks frames by reading u32 LE length and seeking past the body — cursor and accounting can never drift (documented). `append_record`: counter → encrypt → append [u32 len][sealed] → fsync; returns bytes consumed. `read_record_by_index`: walk frames, decrypt target with its index as counter (which must match the AAD binding).
- `derive_record_base_nonce(key, file_id)`: XChaCha20-Poly1305 encrypt of 8 zero bytes under an all-zero nonce with the nonce-derive domain AAD (safe exactly once per key+domain), then XOR-folded with the file_id into 24 bytes. The long comment explains this is a PRF-style expansion bound to (key, file_id) and that nonce reuse is prevented because the counter starts at 0 per open handle.
- Drop wipes the key. Tests: roundtrip (3 records), clobber refusal, wrong passphrase, header bit-flip rejection (salt byte), record bit-flip rejection (ciphertext body), KDF-param transplant guard, **record transposition test** (swap frames 0 and 2 → at least one read fails), no-plaintext-leak canary scan (raw file scanned in windows for the secret), 50-record count test, and an #[ignore]d frame-anatomy debug probe kept from the debugging session.

### cerebrum-token internals (all read in full)

**varint.rs** — unsigned LEB128 (7-bit chunks + continuation bit), u32 and u64 variants with explicit overflow guards (shift ≥ 35 for u32, ≥ 70 for u64, max 5/10 bytes). Zigzag for i32/i64 (0→0, -1→1, 1→2...). Signed varint = zigzag + varint. Sequence batch helpers. Tests: boundaries at 127/128, 16383/16384, u32::MAX, truncated/too-long rejection, zigzag roundtrip, empty sequences.

**compress.rs** — the token compressor. Format: `[token_count][first_token][delta1][delta2]...`, first raw, deltas zigzag+varint (i64 zigzag to cover the full u32 range). ### cerebrum-signatures/simd.rs — the SIMD layer (read in full)

Three paths with runtime dispatch, cached in an AtomicI8 (first call detects, then reads a relaxed load):

## 15. Portal:data — The Tool Layer and Remaining Infrastructure (all read in full)

### The registry architecture (the spine every tool rides)

- **The four-file pattern**: every tool set is `{Name}ToolDefinitions.kt` (a `ToolSetRegistration` object: name constants, definitions list, executorClass, extractorClass) + `{Name}ToolExecutor.kt` (`ToolExecutor` impl with a when-dispatch on tool name) + `{Name}ToolResults.kt` (serializable result types implementing `ToolResultData`) + `{Name}ToolSet.kt` (3 lines). 63 registrations exist in `GeneratedToolRegistrations.allRegistrations` (manual placeholder list — KSP generated file replaces it when configured; documented).
- **ToolDefinition** = pure data (name, description, category, parameters, permissions). **ToolParameter** = name, `ToolParameterType` (String/Integer/Long/Boolean/Float/Enum/Code/ShellCommand/Script), required, description, enumValues. **Permissions** carry Android runtime permission strings, checked by the dispatcher.
- **ToolRegistry** — three HashMaps (definitions/executors/extractors) + paramIndex (param name → tool names) for reverse lookup.
- **ToolNameResolver** — three-tier: exact case-insensitive → parameter reverse lookup (single candidate resolves; multiple candidates disambiguate by counting other matching arg keys; no context = fail safely null) → null.
- **ToolSecurityPolicy** — inspects by PARAMETER TYPE, not tool name: ShellCommand/Code/Script values get sed (all positions), `perl -i/-ie/-pe`, `awk -i inplace`, `python open()` write-mode blocks — "use the editFile tool" messages.
- **ToolArgumentRepair** — the LLM-argument fixer: empty-key detection and orphan rescue, `__wrapped_value__` unwrapping, fuzzy param name matching (case, quote-strip, snake↔camel both ways, contains, 3-char prefix), type coercion per declared type, orphan values assigned to missing required then optional then positional. Output: Map<String, Any?> with primitives unwrapped (isString/content, true/false, double if contains '.', else long, else string).
- **ToolSchemaSerializer** — ToolDefinition → OpenAI-compatible JSON schema; `serialize()` (full envelope), `serializeParameters()` (flat parameters object for the Ollama wire — the documented Fix 1 nesting fix), enum values carried.
- **ToolDispatcher** — the 9-step flow: resolve name (rawArgs for disambiguation) → registry miss = UNKNOWN_TOOL → definition → Android runtime permission loop (missing = PERMISSION_DENIED; AiRepositoryImpl triggers PermissionGateway broadcast) → security policy → argument repair → executor.execute → extractor fallback when resultObject null → ToolDispatchResult (resolvedName/rawJson/resultData/resultObject/success/error/status; factories unknownTool/permissionDenied/blocked/executionError/success).
- **ToolExecutionResult** — rawJson + resultData + resultObject + success + error. **DispatchStatus** enum: SUCCESS/UNKNOWN_TOOL/PERMISSION_DENIED/SECURITY_BLOCKED/EXECUTION_ERROR.
- **MediaLibraryToolsRegistration** — documentation shim (media trio names). **ToolsConstants.kt** — intentionally empty (constants live with their definitions files).

### Second sweep — the Kotlin brain-engine twin stack, discovery managers, and remaining infrastructure (all read in full)

**The Kotlin memory-engine twin stack.** These are ports of Cerebrum's crates to Kotlin that predate the Rust-brain migration; the one-store boundary reset made the Rust brain the live memory path (BrainService/CerebrumBrainApi), and these remain compiled and partly wired. Where each stands:

- **QueryEngine** — four-tier Reciprocal Rank Fusion retrieval: hot cache (via PrefetchEngine, weight 1.5), FTS (LIKE-term merging ranked by term-match frequency — documented: the DAO uses LIKE not FTS5 MATCH, so individual terms are queried and merged rather than passing a literal FTS5-syntax string), Signature (weight 0.7), DVM (weight 1.0 — replaces the dead TFLite embedding tier per its own doc), graph boost (weight 0.2), RRF_K=60, plus a 24h-half-life recency boost (exp decay × 0.15) and per-result source tracking joined as "CACHE+FTS+…".
- **PolicyEngine** — query classification SPECIFIC/CONCEPTUAL/ENTITY/RECENT/GENERAL by word count/length/keyword patterns (entity patterns: steven, sheldon, lux, nexus, guru, mac, bristol; technical patterns: database, schema, migration, context, compaction, memory, brain, embedding, signature, decay, graph, engine, code, build, fix, bug); hybrid tier activation (base tiers per primary type + EMBEDDING for technical short queries + FTS for conceptual + SIGNATURE as cheap first-pass whenever FTS is on); enableGraph for entity/conceptual/general/technical.
- **SignatureEngine** — the Kotlin 256-bit signature: DJB2-style stableHash, 3 bit positions per word + 2 per bigram, stop-word filtered, Base64 storage, hammingDistance/similarity, search at minSimilarity 0.35. **LIVE**: AiRepositoryImpl calls generateSignature for every tool-result row.
- **EmbeddingEngine** — 768→256 random projection (Johnson-Lindenstrauss, Gaussian matrix seeded 42, 1/sqrt(768) scaling), cosine similarity, search skipping facts with no stored embedding. Its producer (LocalEmbeddingService) is now a **stub** — the EmbeddingGemma TFLite model compiled 169+ subgraphs and blocked startup 5+ seconds, so it was removed to fail cleanly; this lane is dead by design, which is exactly why QueryEngine's Tier 4 uses DVM instead.
- **GraphEngine** — typed edges SEMANTIC/TEMPORAL/CAUSAL/ENTITY; buildSemanticEdges at similarity ≥0.5; temporal chain edges; BFS that loads edges per-visited-node only (queries = visited nodes, not total edges); getConnectedFacts over semantic+entity.
- **CurationEngine** — domain classification by keyword scoring (GURU_PROJECT / USER_PERSONAL / BUSINESS / TECHNICAL / PREFERENCE) with category overrides; topic/subtopic extraction; cross-references at >0.9 DUPLICATE / >0.6 RELATED / >0.3-and-same-domain RELATED.
- **EpisodicEngine** — sentiment lexicon with ±1..3 weights (Bristol slang included: lush, mint, proper job, safe; heavy negatives included), negation flip on the previous 1–2 words, amplifier ×1.5 boost, caps-ratio / exclamation / repetition intensity boosts, normalised to [-1,1]. ### guru-server — the binary

**main.rs** — env: DATABASE_URL (default guru_server), BIND_ADDR (default 127.0.0.1:4400), CONTENT_DIR (default ./content), and **ADMIN_PASSWORD — mandatory, no default**: `expect("ADMIN_PASSWORD must be set — refusing to boot with an open admin surface")`. Boot: tracing init → setup_database → create CONTENT_DIR/_staging → AppState → router merge: public + review + master + legacy + adpack + chat + /health ("publisher-not-collector") → axum::serve with graceful shutdown on Ctrl+C/SIGTERM.

**state.rs** — AppState (cloneable): content: ContentRepository, reviews: ReviewRepository, content_dir: PathBuf, admin_password: Arc<String> ("lives only in process memory, fed in via the ADMIN_PASSWORD environment variable — nothing stores it... compared in constant time").

**etag.rs** — `Etagged<T>`: serializes the value with a strong ETag + Cache-Control: no-cache (the comment records why: "max-age=300 made panel edits invisible for up to five minutes"). `if_none_match_304`: splits the If-None-Match values, strips W/ prefixes (weak comparison), matches exact or `*` → 304 with the same ETag.

**public.rs — the publisher surface (all tokenless by design).** Routes: /v1/manifest (ETag = "guru-manifest-{content_state_hash}", body = generated_at + per-type slug/version lists), /v1/prompts + /{slug}, /v1/skills + /{slug}, /v1/tools + /{slug}, /v1/agents + /{slug} (agent ETag = slug only; agents carry no version by design), /v1/canvas-packs + /{slug} (pack + elements together) + /{slug}/elements, /v1/canvas-media/{element_id}, /v1/config (flat key→value map), /v1/builtin-masks (guru_content::built_in_masks() served from the binary — "so a fresh install has agents before it ever syncs the community catalog"). Per-type list ETags: sha256 over sorted `slug:version:updated_at` rows. Canvas media: media_path must canonicalize inside content_dir ("path escapes content dir" → 403), Content-Type from media_mime, ETag "media-{id}", Cache-Control no-cache (the comment: "a 24h max-age here froze previews after edits the same way the JSON ETag bug did").

**review.rs — the community pipeline (public submit + authed review).** POST /v1/submit/{content_type}: content_type in [skill, tool, agent, canvas_pack]; 2MB body cap ("submit media packs by URL" on 413); JSON parse; slug required + `valid_slug` (lowercase ascii + digits + single dashes, ≤64, no edge/double dashes); name required; **the PII guard** — `contains_pii_keys` walks every parsed key recursively, case-insensitive substring match against ["email","phone","address","password","account","ssn","ip_address","user_id"] ("authors can be creative ('contact_email','userPhone')") → any hit = 400 "submissions must not contain personal fields; keep them publishable-only"; author_label optional. Review routes all behind `require_reviewer` — the constant-time gate: reads the Bearer value as RAW BYTES, strips "Bearer ", then two accepted encodings — raw bytes (curl/CLIs) and the browser ByteString one-byte-per-char decode (so £ as 0xA3 works from fetch()); both compared as sha256 digests folded byte-OR so "branch predictors learn nothing". approve: fetch pending → promote payload into the right catalog table (promote_skill/tool/agent/canvas_pack, each mapping every payload field with the row defaults for absent fields; canvas element promotion inline with the script/text_content swap for script-type elements) → approve_submission (payload nulled). reject: reject_submission (payload nulled same statement) + `purge_staged_media` removes content_dir/_staging/{submission_id} recursively. list_pending strips full payloads from the queue ("reviewers fetch the individual submission for the payload").

**master.rs — the gated publisher console.** Routes for prompts (create/update-by-slug/get-with-versions), skills, tools, agents, canvas packs + elements (add/replace/update/activate), studio assets (list summary 200 newest / upload / delete / media), config set, activation switches for every type (/activate/{true|false}), and hard deletes for everything. `require_token` is the same constant-time check as require_reviewer, made `pub` so the chat route reuses the exact gate. Studio assets: uploads are base64 JSON (10 MiB decoded cap — 413 beyond), body limit raised to 15 MiB for the base64 overhead ("a JSON body above 2 MB with the default limit errors out with 'Failed to buffer the request body'"), file_type 'lottie' serves as application/json else octet-stream; everything no-cache. Element editing: `parse_elements` maps a JSON array to ElementInputs with every default mirrored from the migration (text_colours default ["#DAA520"], sort_order falls back to array index, etc.). Delete responses carry the doctrine text: "{slug} deleted — gone from the database".

**legacy.rs — the app's four tokenless endpoints.** GET /prompts/assembled: selects active prompt_sections with delivery_mode IN ('always','session_start') and category IN (agi_law, tool_calling, identity, constitution, capabilities, context, operating, personality, other), ordered by the legacy category ranking (agi_law→0 ... other→8→else 9) then name, joined with "\n\n", returned as {"prompt": String, "version": 1}. "The Android app (every released build) fetches four routes from the Unus Lumen API in these exact shapes... tokenless by design (matching the app's tokenless wiring since commit b1638c5)." GET /api/llm-config: reads config_defaults.llm_config, merges any missing key from the honest fallback json — base_model "glm-5.3-flash:cloud", fallback_models ["glm-5.3:cloud"], temperature 1.2, max_tokens 131072, context_window 1000000, thinking_level "max", top_p 0.9, top_k 40, repeat_penalty 1.1, seed 0 — "so old builds never crash"; missing row = 503 "llm_config not seeded". GET /api/metadata-config: config_defaults.metadata_config verbatim (MetadataConfig serde shape) or 503. GET /api/hive-prompts: active hive_drive-category prompt sections as a slug→content bundle; empty = 503 "hive_prompts not seeded". These four are exactly the endpoints PromptFetcher/LlmConfigFetcher/MetadataConfigFetcher/HivePromptFetcher hit in §10 — the publisher dependency of the app is this file.

**adpack.rs — the loading space server side.** GET /api/adpack: selects the active pack that HAS AT LEAST ONE ACTIVE ELEMENT, newest updated_at first — the comment records the fix: "An empty active pack previously won (newest updated_at) and served entries:[], which the app then cached over its last good pack, blacking out the canvas." No qualifying pack = `empty_pack()` (zero UUID, box_height_dp 30, empty entries — a valid honest response). entry_json: one element == one entry (flat schema by design) — lottie_file_name = the element name, every entry-level animation field read straight from the row, elements: [element_json(row)] where element_json carries geometry + z_index=sort_order + text + lottie/script fields (image/video file/data fields present as nulls in this flat shape). Media: /api/adpack/entry-media/{entry_id} and /api/adpack/media/{element_id} both hit serve_element_bytes — path canonicalization inside content_dir, extension→MIME map (json/lottie/png/jpg/jpeg/gif/webp/webm/mp4/svg), Cache-Control "public, max-age=300" (media here, unlike the master surface, tolerates 5-minute caching). **The hex-healing path**: panel-era payloads saved as hex text (optional "\x" prefix, hex digits, whitespace) are detected (even length, all hex digits, decodes), decoded, and if the decode starts with { or [ (real JSON) the file on disk is HEALED with the decoded bytes — "subsequent reads are native JSON"; anything that fails verification serves unmodified.

**chat.rs — the chat proxy with keyword injection.** POST /api/chat is **token-gated with the same admin bearer** ("this route spends the host's model compute, so it is gated like every other non-public surface") — and carries a live known-cost comment: "Known cost (2026-10-17): shipped app builds on the default UnusLumen provider call this route tokenless and receive 401 until a build ships its own credentials. Deliberate while the app-side auth path is worked out." `forward_stream` pipes the body to UNUSLUMEN_MODEL_URL (default http://localhost:11434 — the model gateway) and streams the NDJSON response back byte-for-byte unbuffered; no overall client timeout by design ("model streams can run for minutes and cutting a live stream is worse than waiting"). `inject_keyword_prompts`: parse body → find the LAST user message (string content or array-of-text-parts form) → lowercase, split to words → load active keyword_injection prompts (one cheap SELECT per chat; per-prompt match_threshold falling back to global_threshold, both defaulting 0.75) → `phrase_matches`: slide the trigger phrase across the user's words; a match needs a consecutive window where every word pairs at/above the Jaro-Winkler threshold AND a length ratio ≥ 0.7 (the guard exists because "Jaro-Winkler's prefix bonus inflates scores for words of very different length ('show' scores 0.80 against 'shocking')" — 0.7 keeps typos like 'rightt' in and rejects prefix-lookalikes) → on match, splice `<note to self>\n{content}\n</note to self>` blocks for every matched prompt as a system message BEFORE the last user message. `${human}` is replaced with empty: "this server stores no users by design, the display name stays on the device." **Every failure path returns the original body** — "injection never breaks a chat."

**bin/guru-seed.rs** — idempotent bootstrap: setup_database → insert_agent for all 21 masks (upsert-only by slug). "Reviewer tokens are retired — auth is the single ADMIN_PASSWORD env var on the server, set by deployment."

**bin/guru-import-prompts.rs** — the legacy migration tool: SOURCE_URL (default guru_dev) opened read-only with a hard belt (`SET default_transaction_read_only = on` — "fail the run immediately if a write ever slipped through"), reads master_prompts (name/category/content/version/is_active/delivery_mode/trigger_keywords/match_threshold), closes the source, then upserts each into the new DB with slugify() (lowercase, non-alnum→dash, collapse dupes, trim, 80-char cap, "unnamed-section" fallback) and re-deactivates rows that were inactive.

### Observations on the Server

- **The master GET asymmetry.** `master_get_prompt` checks the token; `master_get_skill`/`master_get_tool`/`master_get_agent`/`master_get_pack` do NOT (they take `_headers` unused) — they serve exactly the same data the tokenless public /v1 routes already serve, so nothing new leaks; only the prompt GET is gated because it attaches the version history the public surface never exposes. Consistent when read that way, but the signature difference is easy to misread.
- **The chat 401 is a live operational fact, by the code's own record** — the default UnusLumen provider path in shipped app builds cannot authenticate to this route yet. Anyone debugging "default provider returns 401" should start here, not in the app.
- **The app's four legacy fetch paths are all here** and all tokenless; the "publisher, not collector" name is earned by the schema: zero user tables, PII-guarded submissions, payloads nulled on decision, tokens hashed.
